## 1. 배경 및 목적

성경을 읽다가(예: 창세기 2장) 등장하는 인물·지명·사건 이름을 사이드바 카드에서 클릭하면, 해당 인물/지명/사건에 대한 참고자료 포스트 페이지로 이동하는 구조.

- **사이드바 카드**: 3~4줄 요약, 클릭 유도용 (이 지침의 범위 밖)
- **포스트 페이지**: 이 지침이 다루는 본문. 카드를 클릭해 넘어온 독자, 즉 이미 해당 장(章)을 읽고 있어 어느 정도 맥락을 가진 독자를 대상으로 함

일반 대중을 위한 개인 블로그 에세이가 아니라, **모줄성 참여자를 위한 참고자료**라는 점이 구조와 톤을 결정하는 핵심 기준.

## 2. 기본 구조 (5단계)

원자료(백과사전식 자료)의 항목 나열 순서를 그대로 따르지 말고, 아래 5단계로 재구성한다.

| 단계 | 내용 | 비고 |
|---|---|---|
| 1. 도입 | 인물/지명/사건을 한두 문장으로 압축 소개 | 낯선 독자를 붙잡는 훅이 아니라, 이미 맥락 있는 독자에게 바로 답을 주는 방식 |
| 2. 배경 | 등장하는 장(章), 인물이라면 창조/기원 등 | 원자료의 도입부·정의 부분 활용 |
| 3. 핵심 전개 | 시간순 사건 또는 주제별 속성 | 소제목으로 구간을 나눔 (아래 3장 참고) |
| 4. 성경 전체에서의 의미 | 신약 등에서 재조명되는 부분, 신학적 의의 | 설교조가 아니라 사실 위주로 서술 |
| 5. 마무리 | 함께 읽으면 좋은 구절(다음이야기는 작성하지 말것) |

## 3. 유형별 소제목 구성

### 인물 (시간순 사건이 있는 경우 — 예: 아담)
- 창조/등장 배경
- 핵심 사건을 시간순으로 2~4개 섹션으로 분리 (예: "단 하나의 규칙" → "하와의 탄생" → "타락" → "추방")
- 성경 전체에서의 의미 (신약 재조명 등)

### 인물/존재 (시간순 사건이 아니라 속성·주제 중심인 경우 — 예: 하나님)
- 정의 및 핵심 속성
- 이름/호칭별 의미
- 관계 (다른 인물/인류와의 관계)
- 주권/역할 등 신학적 주제
- 심판과 은혜, 예배 등 나머지 주제 섹션

### 지명
- 위치 및 지리적 배경
- 이곳에서 일어난 사건들
- 상징적 의미

### 사건
- 배경 (왜 이 일이 일어났는가)
- 전개와 결과
- 이후 영향 (교리적 의미, 구원사적 위치 등)

## 4. 문장 작성 원칙

- **원자료 인용은 최소화, 서술은 재구성**: 성경 구절은 필요한 경우에만 짧게 인용하고, 나머지는 문맥으로 풀어서 쓴다. 원자료의 영어 문장을 그대로 번역하지 않는다.
- **소제목 아래 문단은 1~2개로 압축하지 않는다**: 원자료 내용을 다 살리되 자연스러운 한국어 문장으로 새로 쓴다. 참고자료라고 해서 지나치게 짧게 요약하면 정보가 누락되므로, 원자료의 각 항목이 최소 한 문단 이상 분량으로 반영되어야 한다.
- **원자료의 모든 주요 항목을 포함**: 분량 조절을 이유로 원자료의 항목을 임의로 생략하지 않는다. (예: "예배와 경외", "계시와 성경" 같은 항목도 빠뜨리지 않고 포함)
- **개인적 반응·수사적 질문 금지**: "나라면 어땠을까", "당신이라면 어떤 선택을 했을까" 같은 1인칭 성찰이나 독자에게 던지는 질문은 넣지 않는다. 이 글은 개인 에세이가 아니라 참고자료다.
- **문단 전환 문구는 필요시에만**: 구조 단계가 바뀌는 지점(예: 사건 전개 → 신학적 의의)에서 "여기서부터는 ~" 같은 이정표 문장을 넣어도 되지만, 남용하지 않는다.

## 6. 분량 기준

- 소제목 3~5개 기준, 각 섹션 1문단(3~5문장) 이상
- 원자료의 항목 수가 많을수록(예: 하나님 — 10개 항목) 소제목 수도 비례해서 늘어남
- "사이드바 카드보다는 확실히 길고 읽을 만한 글"이라는 느낌이 기준 — 지나친 압축은 지양

## 7. 최종 산출물 형식 (JSON)

포스트 페이지는 아래 JSON 스키마로 최종 정리한다.
filename은 {slug}.json
```json
{
  "slug": "adam",
  "title": "아담 — 최초의 인간, 최초의 죄인",
  "subtitle": "에덴에서 추방까지",
  "excerpt": "아담은 창세기에 등장하는 첫 사람으로, 하나님의 형상대로 지음받았다. 에덴동산을 돌보는 임무를 맡았지만 선악과를 먹지 말라는 명령을 어겨 타락하고, 결국 동산에서 쫓겨난다. 그의 불순종은 인류 전체의 죄와 연결되며, 훗날 '둘째 아담'인 예수 그리스도와 대조를 이룬다.",
  "contents": "#### 문단 제목\n(문단 마크다운 전체)\n\n### 문단제목\n문단\n",
  "categories": ["성경이야기", "인물이야기"],
  "tags": ["아담", "창세기", "타락", "에덴동산"]
}
```

### 필드별 작성 기준

| 필드 | 기준 |
|---|---|
| `slug` | 영문 소문자, 하이픈 구분 (예: `adam`, `garden-of-eden`) |
| `title` | 인물/지명/사건의 한글 이름을 포함한 제목 (예: "아담 — 최초의 인간, 최초의 죄인") |
| `subtitle` | 부제목 |
| `excerpt` | 250~300자. 도입부와 핵심 사건을 압축한 요약. 카드 미리보기나 목록 페이지에 노출될 수 있으므로 본문을 읽지 않아도 전체 흐름이 파악되도록 작성 |
| `contents` | 6장 구조를 따른 본문 전체를 마크다운으로, 문단 title은 '####'. `contents` 필드 안에서는 `\n`으로 줄바꿈 |
| `categories` | 첫 번째 값은 항상 `"성경이야기"` 고정, 두 번째 값은 유형에 따라 `"인물이야기"`(person) / `"지명이야기"`(place) / `"사건이야기"`(events) 중 하나 |
| `tags` | 인물/지명/사건 이름, 등장 장(章) 관련 키워드, 핵심 사건명 등 3~6개 |

## 8. 체크리스트 (포스트 작성 후 확인)

- [ ] 원자료의 모든 주요 항목이 포함되었는가
- [ ] 5단계 구조(도입-배경-전개-의의-마무리)를 따르고 있는가
- [ ] 성경 인용이 짧고 자연스러운 한국어 서술로 재구성되었는가
- [ ] 개인적 성찰/수사적 질문이 들어가지 않았는가
- [ ] 유형(인물/지명/사건)에 맞는 소제목 구성을 따르고 있는가
- [ ] 최종 결과물이 지정된 JSON 스키마(slug, title, subtitle, excerpt, contents, categories, tags)에 맞게 정리되었는가
- [ ] excerpt가 250~300자 기준을 충족하는가
